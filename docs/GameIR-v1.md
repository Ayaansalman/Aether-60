# GameIR v1.0 Specification Contract

This document provides the definitive specification of **GameIR (Game Intermediate Representation) v1.0**, the formal data contract consumed by the Phaser 3 frontend and generated by the AETHER planning/repair pipeline.

---

## 1. Specification Overview

GameIR v1.0 decouples LLM generation from client rendering. Rather than generating raw executable JavaScript or Python code (which is unsafe, prone to runtime syntax crashes, and difficult to test), the LLM synthesizes a strongly-typed declarative JSON document. 

All models are defined with **Pydantic v2** (`aether-backend/schemas/game_ir.py`) with strict bounds checking and `extra="forbid"` to reject unmapped attributes.

---

## 2. Top-Level Schema (`GameIR`)

```json
{
  "schema_version": "1.0",
  "title": "Dungeon Crystal Run",
  "genre": "arena_survival",
  "premise": "A wizard navigates a subterranean dungeon gathering glowing mana crystals while dodging relentless wraiths.",
  "theme": "spooky",
  "player": {
    "move_speed": 220.0,
    "max_health": 3,
    "attack_mode": "projectile"
  },
  "enemies": [
    {
      "type": "chaser",
      "count": 6,
      "speed": 130.0
    }
  ],
  "collectibles": [
    {
      "type": "crystal",
      "count": 10
    }
  ],
  "objective": {
    "type": "collect_count",
    "target": 8
  },
  "difficulty": 3,
  "controls": {
    "movement": "WASD or arrow keys",
    "attack": "Space"
  },
  "seed": 42
}
```

### Top-Level Field Descriptions

| Field | Type | Validation Rules | Description |
|---|---|---|---|
| `schema_version` | `Literal["1.0"]` | Constant `"1.0"` | Enforces schema version compatibility. |
| `title` | `str` | `1 <= len <= 50` | Human-readable game title displayed in HUD. |
| `genre` | `Literal["arena_survival"]` | Enforced constant | Single supported archetype for 60% milestone. |
| `premise` | `str` | `1 <= len <= 240` | Natural language narrative summary. |
| `theme` | `Enum` | `fantasy \| sci_fi \| pirate \| spooky \| cozy` | Dictates visual color palette, sprite representations, and asset tinting. |
| `difficulty` | `int` | `1 <= difficulty <= 5` | Stated difficulty rating (1 = easiest, 5 = hardest). |
| `seed` | `Optional[int]` | Integer or `null` | Deterministic seed for reproducible entity spawns. |

## 3. Component Schemas

### 3.1 Player Configuration (`PlayerConfig`)
- `move_speed`: `float` clamped to `[100.0, 300.0]` px/s.
- `max_health`: `int` clamped to `[1, 10]`.
- `attack_mode`: `Literal["projectile", "melee", "avoid_only"]`.
  - `"projectile"`: Player shoots ranged bolts using Space key (cooldown 0.3s).
  - `"melee"`: Player emits an orbital cleave blade using Space key (radius 60px).
  - `"avoid_only"`: Player has no offensive capability; must survive purely through evasion.

### 3.2 Enemy Configuration (`EnemyConfig`)
- `type`: `Literal["chaser", "bouncer", "patroller", "dasher", "shooter"]`.
  - `"chaser"`: Moves directly toward player's Euclidean coordinates at constant velocity.
  - `"bouncer"`: Maintains constant diagonal velocity (45°), ricocheting off arena boundaries and layout obstacles.
  - `"patroller"`: Moves back and forth along horizontal or vertical lanes, reversing direction at arena bounds or obstacles.
  - `"dasher"`: Stalks player at slow speed, periodically freezing/winding up before lunging directly at player's position.
  - `"shooter"`: Maintains standoff distance from player, periodically firing avoidable projectiles toward player.
- `count`: `int` clamped to `[1, 50]`. Active enemy count in the arena (up to 2 types per game).
- `speed`: `float` clamped to `[20.0, 250.0]` px/s.

### 3.3 Collectibles Configuration (`CollectibleConfig`)
- `type`: `Literal["crystal", "battery", "coin", "gem", "star"]`.
- `count`: `int` clamped to `[0, 50]`. Number of collectible items placed in the arena.

### 3.4 Objective Configuration (`ObjectiveConfig`)
- `type`: `Literal["survive_seconds", "collect_count", "defeat_enemies"]`.
- `target`: `int`.
  - If `type == "survive_seconds"`: target must satisfy `5 <= target <= 120` seconds.
  - If `type == "collect_count"`: target must satisfy `1 <= target <= 20` items.
  - If `type == "defeat_enemies"`: target must satisfy `1 <= target <= 30` defeated enemies. Enemies automatically respawn if remaining alive count is less than needed to win, ensuring reachability. Rejected if `player.attack_mode == "avoid_only"`.

### 3.5 Arena Layout (`arena_layout`)
- `arena_layout`: `Optional[Literal["open", "pillars", "lanes", "maze"]]` (default `"open"`).
  - `"open"`: Unobstructed 800x600 arena with outer perimeter walls.
  - `"pillars"`: 4 symmetric solid obstacle blocks providing tactical cover.
  - `"lanes"`: Horizontal partition barriers with safe navigation gaps.
  - `"maze"`: Wide inner corridor structure with no dead ends, guaranteeing player is never trapped.
  - *Safety invariants*: Obstacles are never placed at the player spawn point (400, 300) and maintain at least 32px clearance from outer perimeter walls.

### 3.6 Visual Overrides (`visual_overrides`)
- `visual_overrides`: Optional configuration for customized presentation:
  - `player_label`: `Optional[str]` (max 24 characters) displayed in HUD legend.
  - `enemy_label`: `Optional[str]` (max 24 characters) displayed in HUD legend.
  - `collectible_label`: `Optional[str]` (max 24 characters) displayed in HUD legend.
  - `player_shape`: `Optional[Literal["circle", "square", "triangle", "diamond"]]`.
  - `enemy_shape`: `Optional[Literal["circle", "square", "triangle", "diamond"]]`.
  - `accent_hex`: `Optional[str]` (#RRGGBB hex color code) overriding primary HUD/border accents.

### 3.7 Controls Configuration (`ControlsConfig`)
- `movement`: `str` (1-50 chars), e.g. `"WASD or arrow keys"`.
- `attack`: `Optional[str]` (max 50 chars), e.g. `"Space"` or `null` for avoid-only.

## 4. Constrained Repair Patch Schema (`GameIRPatch`)

When automated QA detects that a generated spec fails playability smoke checks (e.g. player survival < 3s), the self-repair agent proposes a delta patch adhering strictly to `GameIRPatch`:

```json
{
  "player_move_speed": 240.0,
  "player_max_health": 5,
  "enemy_speed_multiplier": 0.75,
  "enemy_count": 8,
  "objective_target": 20,
  "difficulty": 3,
  "rationale": "Reduced enemy speed by 25% and increased player health from 1 to 5 to satisfy idle survival requirements."
}
```

### Allowed Patch Fields:
- `player_move_speed`: New player speed (clamped to `[100.0, 300.0]`).
- `player_max_health`: New health points (clamped to `[1, 10]`).
- `enemy_speed_multiplier`: Scaling factor applied to existing enemy speeds (resulting speed clamped to `[20.0, 250.0]`).
- `enemy_count`: Reduced enemy density (clamped to `[1, 50]`).
- `objective_target`: Adjusted target seconds or item count.
- `difficulty`: Re-calibrated difficulty rating `[1, 5]`.
- `rationale`: Human-readable justification of the parameter patch.

### Explicitly Forbidden in Repair:
- Changing `genre` (must remain `arena_survival`).
- Changing `theme` (e.g. cannot turn a pirate game into a fantasy game).
- Changing `title` or `premise`.
- Changing `objective.type` (cannot switch between survival and collection).
- Changing `player.attack_mode` (cannot grant weapons to an avoid-only game).
- Arbitrary code execution or unmapped keys (`extra="forbid"`).
