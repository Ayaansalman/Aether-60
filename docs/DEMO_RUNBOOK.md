# AETHER Live Demo Runbook (Phase 6 / Blueprint Section 15.3)

This runbook specifies the exact procedure, rehearsed prompts, failover protocols, and quota hygiene guidelines for presenting the **AETHER Game Synthesis & Self-Repair System** live.

---

## 1. Golden Rules of the Presentation

1. **NEVER DEBUG ON STAGE**: If a live network call fails, times out, or hits a 429 limit, **do not open a terminal or edit code on stage**. Immediately switch to the **"Saved result (offline demo)"** row in the Forge UI. The saved demos are bundled from real model evaluation artifacts and load instantly with zero network dependencies.
2. **ONE REHEARSED LIVE PROMPT**: Use the exact prompt tested during qualification. Avoid ad-hoc, overly complex, or open-ended prompts during the scored evaluation.
3. **STRICT QUOTA HYGIENE**: Google AI Studio free-tier quota resets around **08:00 UTC (1:00 PM Pakistan Standard Time)**. Follow the quota protection protocol detailed in [Section 6](#6-quota-hygiene--rate-limits).

---

## 2. Pre-Flight Verification & Launch Commands

Run all commands from PowerShell in the project root directory.

### Step 1: Clean Any Hanging Processes
Ensure ports 8000 (FastAPI) and 5173 (Vite) are completely clear:
```powershell
powershell -ExecutionPolicy Bypass -File scripts\stop_all.ps1
```

### Step 2: Run Pre-Flight Demo Check
Verify environment health, API key configuration, and offline fallback integrity:
```powershell
& "aether-backend\venv\Scripts\python.exe" scripts\demo_check.py
```
> **Note:** Do NOT pass `--ping` on stage or right before the presentation unless you specifically need to verify live upstream connectivity. The default run performs all checks without consuming model generation quota.

### Step 3: Launch Dev Servers & Open Forge
```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_all.ps1
```
This script will:
1. Print the **Active Provider** (`openai_compat`), **Model ID** (`gemini-3.5-flash-lite` or configured model), and fallback status in a banner.
2. Start the FastAPI backend on `http://localhost:8000`.
3. Start the Vite dev server on `http://localhost:5173`.
4. Wait for `/api/v1/health` to confirm backend readiness.
5. Launch the default web browser directly to `http://localhost:5173/forge`.

## 3. The Rehearsed Live Demonstration

### Live Generation Prompt
In the Forge prompt input, enter the rehearsed prompt (or click the **Spooky Wizard** chip):
```text
a spooky wizard collecting glowing crystals in a dark dungeon while ghosts chase me
```

### What to Walk Through While It Synthesizes (~45–60 seconds)
1. **Pipeline Lifecycle Stages**: Point out the progress stepper moving through `PLANNING` -> `VALIDATING_SPEC` -> `BUILDING` -> `TESTING`.
2. **GameIR Structural Contract**: Explain that the model does not generate arbitrary code; it synthesizes a strictly bounded **GameIR v1 specification** (player speed, collision geometry, objective targets, enemy count).
3. **Automated Headless Playwright QA**: Point out the `TESTING` stage. Explain that AETHER launches a headless Chromium instance running 17 deterministic QA checks (measuring movement consistency, player survival, flee-bot survivability, and objective triggers).
4. **Manifestation Complete**: Show the QA report summary: 17/17 critical checks passed, zero runtime exceptions.
5. **Launch Playable Simulation**: Click **PLAY SIMULATION** to play the synthesized game in Phaser. Point out WASD movement, ghost chasers, glowing crystal pickups, and the live HUD.

## 4. Stage Failure Recovery Protocol (What To Do If Live Call Fails)

If the live generation fails due to a network glitch, Google AI Studio rate limit, or timeout:

### Immediate Action: Zero-Delay Pivot
1. Do **NOT** open the terminal, inspect logs, or restart servers.
2. Directly above the example prompts, look at the **"Load saved demo"** row labeled **`Saved result (offline demo)`**.
3. Click any of the three real evaluation artifacts:
   - **`Spooky Crystal Dungeon`** (`gemini-3.5-flash-lite (Run A)`) — Standard clean 1-shot generation.
   - **`Pirate Cove Treasure Hunt`** (`gemini-3.5-flash-lite (Run A)`) — Island survival scenario.
   - **`Shadow Pursuit (Repaired)`** (`gemini-3.5-flash-lite (Run A2 Real Repair)`) — **The Self-Repair showcase**.
4. Say to the committee:
   > *"Because upstream AI APIs can fluctuate, AETHER features an offline resilience layer. Here is the verified evaluation artifact generated by Gemini 3.5 Flash Lite under identical pipeline constraints."*
5. The Forge UI will instantly populate:
   - Full lifecycle events from the evaluation run.
   - Real Playwright QA checks and measurements.
   - For `Shadow Pursuit`: the real before/after repair diff (decreasing chaser count from 50 to 8, reducing speed from 250 to 100 px/s, increasing player health from 1 to 8) and the model's rationale.
6. Click **PLAY SIMULATION** to play the game. The static game loads immediately with zero backend or network calls.

## 5. Automatic Fallback Chain Behavior

If a live generation encounters a rate limit or server error:
- AETHER automatically transitions across the configured fallback chain:
  $$\text{gemini-3.7-flash} \longrightarrow \text{gemini-3.6-flash} \longrightarrow \text{gemini-3.5-flash-lite} \longrightarrow \text{gemini-3.1-flash-lite}$$
- **Rate Limit (429 Daily Exhaustion):** Handled immediately without useless retries; moves to next model in the fallback list.
- **Rate Limit (429 Per-Minute):** Handled with a single polite backoff capped at 65 seconds before attempting fallback.
- **Server Overload (503 / Timeout):** Recorded and transferred to the next fallback candidate.
- All transitions are logged in SQLite events and displayed in the Forge Technical Drawer.

## 6. Quota Hygiene & Rate Limits

The Google AI Studio free tier enforces strict daily and per-minute request limits:
- **Free-Tier Reset Window**: The daily quota window resets around **08:00 UTC (1:00 PM Pakistan Standard Time / PKT)**.
- **The Day Before Presentation**:
  - Do **NOT** run batch evaluation benchmarks (`run_eval.py` or `run_real_eval.ps1`) after 1:00 PM PKT.
  - Limit live model calls to **exactly one end-to-end rehearsal run**.
  - All other UI, Phaser styling, and navigation testing must be performed using `MODEL_PROVIDER=mock` or the saved offline demos.
- **Presentation Day**:
  - Arrive with full daily quota intact.
  - Budget: ~2 model requests per live demonstration.

## 7. Shutdown Procedure

When presentation and testing are concluded, cleanly terminate all processes:
```powershell
powershell -ExecutionPolicy Bypass -File scripts\stop_all.ps1
```
Verify that console ports 8000 and 5173 report clean and closed.
